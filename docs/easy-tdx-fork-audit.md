## 已确认风险

### 1. 供应链和可维护性：中高

原作者仓库与 PyPI 项目当前均不可访问，用户 fork 没有 tags 和 Releases。直接从 `main` 安装会把未来未经审计的提交带入项目，也无法稳定复现环境。

控制措施：使用完整 Git SHA；保存源码归档哈希；依赖写入锁文件；每次升级重新审计差异。不要再执行 `pip install easy-tdx`，也不要依赖同名 PyPI 包以后重新出现。

### 2. Web 服务暴露：高（仅在运行 `easy-tdx serve` 时）

Web CLI 默认监听 `0.0.0.0`，CORS 允许任意来源，未看到身份认证。API 包含服务器切换、回测任务以及策略记录的创建和删除。局域网内其他设备可能访问这些接口。

控制措施：Sequoia-X 第一阶段只导入 Python 行情客户端，不启动它的 Web 服务。若以后使用 Web UI，强制 `--host 127.0.0.1`，收紧 CORS，并给有状态接口增加认证。

### 3. 数据正确性和可用性：中高

它依赖逆向实现的通达信协议和第三方行情服务器。服务器可连接不表示返回数据完整；空表、旧日期、复权差异、市场代码识别错误都可能影响策略。仓库自己的近期提交也多次修复空数据故障转移、分钟线时间和回测参数问题。

控制措施：必须使用 Provider 抽象、哨兵股票、非空与日期新鲜度校验、OHLC 约束、复权口径隔离和 Baostock 影子对照。验证前不得写正式行情表。

### 4. 第三方网页抓取：中

当前 HEAD 新增同花顺公开网页解析，会并发请求多个页面。页面结构、反爬策略和服务条款都可能变化。

控制措施：第一轮不启用 `ths_web`；行业和概念数据继续作为可选补充源，设置缓存、限速和独立失败路径。

### 5. 未签名 EXE：高（如果直接下载运行）

原项目工作流会构建未签名 Windows EXE。当前 fork 没有 Release，但以后若出现二进制产物，不能仅凭仓库名称信任。

控制措施：不运行第三方 EXE；从已审计源码构建，或只把纯 Python 行情模块接入 Sequoia-X。
